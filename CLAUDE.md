# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **composite (Bash) GitHub Action** that creates a native app build on Capawesome Cloud Runners by wrapping the [`@capawesome/cli`](https://capawesome.io/docs/cloud/cli/) `apps:builds:create` command. All logic lives in `action.yml` — there is no `src/`, no build step, and no runtime dependencies.

## Architecture

- `action.yml` is the entire implementation. Two `shell: bash` steps:
  1. **Mask secrets** — masks the token line-by-line (`mask()` helper) with workflow-command escaping (`%`→`%25`, `\r`→`%0D`); required because `::add-mask::` only masks one line per command.
  2. **Create build** — `apps:builds:create`, run with `--json --yes`, piped through `tee` so logs stream live while the JSON tail is captured. `buildId`/`buildNumber` are parsed with `sed -n '/^{/,$p' | jq` (the CLI prints logs before the JSON); `buildUrl` is constructed from `appId` + `buildId`. These are written to `$GITHUB_OUTPUT` and re-exported as action `outputs`.
- The action **waits for build completion by default** and fails on build failure (`detached: true` opts out). Auth is via the `CAPAWESOME_TOKEN` env var (no `login` step). The CLI version is pinned inline (`npx -y @capawesome/cli@<version>`).
- Optional inputs are appended to a bash `args` array only when set, using `if` blocks (not `&&`) to stay `set -euo pipefail`-safe. Artifact inputs (`apk`/`aab`/`ipa`/`zip`) accept `true` (bare flag) or a path. `outputs` require `jq` (preinstalled on GitHub-hosted runners).
- `package.json` holds **only** the version, which release-please bumps. It has no dependencies and is not part of the action runtime.

## Conventions

- Use Conventional Commits — releases and `CHANGELOG.md` are generated by [release-please](https://github.com/googleapis/release-please), configured in `release-please-config.json`. Pre-1.0: `feat:` bumps patch, breaking changes bump minor and are documented in `BREAKING.md`.
- When changing inputs, verify CLI flag names and the mutual-exclusivity rules (`gitRef`/`path`/`url`; `channel` vs `destination`; `detached` vs artifact/deploy flags) against the pinned `@capawesome/cli` version. Pass `${{ inputs.* }}` through step `env:` and quote `"$VAR"` — never interpolate inputs directly into `run:`.

## Commands

- Releases are automated: `.github/workflows/release.yml` runs release-please on every push to `main`, which maintains a release PR. Merging it bumps `package.json`, updates `CHANGELOG.md`, tags, and creates the GitHub release. Nothing is run locally.
- Marketplace publishing is **not** automated: the release-please release is created via the API, which cannot set the Marketplace flag. After merging a release PR, edit the new release in the web UI and select **Publish this Action to the GitHub Marketplace** (requires 2FA).
- The `@v<version>` references in `README.md` carry an `x-release-please-version` annotation, so release-please bumps them in the release PR. Do not edit them by hand.
- CI (`.github/workflows/ci.yml`) runs a live smoke test against Capawesome Cloud: it scaffolds a minimal Capacitor app and uploads it via `path` (so no connected Git repo is needed), then builds it. Requires the `CAPAWESOME_APP_ID` / `CAPAWESOME_TOKEN` repo secrets.
